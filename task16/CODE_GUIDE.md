## Вопросы для самопроверки

1. Почему textContent безопаснее innerHTML для введённого пользователем текста? Он вставляет текст, не исполняя HTML и обработчики событий.
2. Почему нельзя сортировать state через tasks.sort()? sort меняет исходный массив; React ожидает новое значение и предсказуемые обновления.
3. Чем Array.filter отличается от удаления данных? filter возвращает новый массив; в интерфейсе фильтр строится из полного списка и не стирает оригинал.
4. Почему «быки и коровы» хранят код строкой? Чтобы сохранить ведущий ноль и сравнивать позиции цифр.
5. Зачем phase в Simon? Это явное состояние: показываем, ждём ввод, переходим к раунду или завершили. CSS отвечает за вид, а не за правила.
6. Зачем deltaTime в змейке? Частота rAF зависит от монитора; шаг по накопленному времени оставляет скорость постоянной.
7. Почему response.ok проверяется отдельно? fetch не отклоняет Promise при HTTP 404/500 — только при сетевой ошибке.
8. Зачем debounce? Отрисовка поиска происходит после паузы ввода; это не запрос на каждый символ.
9. Где источник правды финансов? json-server и db.json. Копия массива во фронтенде нужна для отображения и обновляется после успешного ответа.
10. Почему useEffect не используется для добавления задачи? Добавление — результат действия пользователя, его место в обработчике события. Effect синхронизирует с внешней системой.
11. Что делает DI? Angular создаёт сервис и передаёт экземпляр компоненту; компонент не создаёт собственную независимую копию хранилища.
12. Почему Next.js нельзя просто открыть как index.html? Приложение использует сборку и серверные динамические маршруты, для них нужен процесс Next.js.

Перед защитой стоит изменить пару задач или стилей и самостоятельно пройти путь данных от формы до массива/сервера и обратно в интерфейс.
